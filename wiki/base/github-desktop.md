# Инструкция по установке и использованию GitHub Desktop

GitHub Desktop — это графическое приложение для работы с Git и GitHub без необходимости писать команды в терминале. Оно подходит и новичкам, и опытным разработчикам, которым удобнее визуально видеть изменения, ветки и историю коммитов.

Официальная страница загрузки: https://desktop.github.com/download/

---

## 1. Системные требования

- **Windows**: Windows 10 64-bit или новее (есть также вариант установки через MSI-пакет для развёртывания в организации).
- **macOS**: macOS 12.0 или новее. Есть отдельные сборки под Apple Silicon (M1/M2/M3/M4) и под Intel.
- **Linux**: официально не поддерживается разработчиками GitHub, но существуют неофициальные сборки от сообщества (форк проекта).

Аккаунт на GitHub не обязателен для установки, но понадобится для входа, синхронизации и работы с pull request.

---

## 2. Скачивание установщика

1. Откройте страницу [https://desktop.github.com/download/](https://desktop.github.com/download/).
2. Сайт обычно сам определяет вашу операционную систему и предлагает нужную кнопку загрузки:
   - **Download for Windows (64bit)** — обычный exe/zip-установщик.
   - **Download for Apple silicon** — для Mac на чипах M1/M2/M3/M4.
   - **Download for Intel chip** — для Mac на процессорах Intel.
3. Если нужен установщик для развёртывания на множестве компьютеров в организации, там же есть ссылка **Download for Windows (MSI)** — MSI-пакет, который можно раскатывать через групповые политики (Group Policy) в Active Directory.
4. Также на странице есть ссылка на **Beta**-канал — там можно получить новые функции и исправления раньше официального релиза, но версия менее стабильна.

Альтернативные способы установки (через менеджеры пакетов):

```bash
# Windows, через winget
winget install github-desktop

# Windows, через Chocolatey
choco install github-desktop

# macOS, через Homebrew
brew install --cask github
```

---

## 3. Установка на Windows

1. Запустите скачанный файл (обычно `GitHubDesktopSetup-x64.exe`).
2. В отличие от многих других программ, у GitHub Desktop нет классического мастера установки с кнопками "Далее" — установка проходит автоматически: файл распаковывается и сразу запускает приложение.
3. Дождитесь окончания процесса — появится окно приветствия GitHub Desktop.
4. Если вы устанавливаете MSI-версию для организации:
   - MSI-пакет извлекает автономный установщик (.exe) и настраивает Windows так, чтобы GitHub Desktop установился при следующем входе пользователя в систему.
   - У пользователя должны быть права на установку приложения в свой профиль (установка идёт в пользовательскую директорию, а не в Program Files).

---

## 4. Установка на macOS

1. Откройте папку **Загрузки** (Downloads) и дважды щёлкните по скачанному zip-файлу GitHub Desktop.
2. После распаковки архива дважды щёлкните по файлу приложения GitHub Desktop.
3. Приложение запустится автоматически сразу после установки.
4. При первом запуске macOS может запросить подтверждение на открытие приложения, скачанного из интернета — подтвердите запуск через **Системные настройки → Конфиденциальность и безопасность**, если потребуется.

---

## 5. Первый запуск и вход в аккаунт

1. При первом запуске откроется экран **Sign in to GitHub.com** (Войти в GitHub.com).
2. Нажмите **Sign in** — откроется браузер, где нужно авторизоваться на github.com и подтвердить доступ приложению (OAuth).
3. После подтверждения вернитесь в GitHub Desktop — вы автоматически будете авторизованы.
4. Если у вас есть аккаунт **GitHub Enterprise**, можно также подключить его отдельно в настройках (Preferences/Options → Accounts).
5. На следующем шаге приложение попросит указать:
   - **Имя** и **email**, которые будут указываться в коммитах (Configure Git).
   - Можно оставить свои данные из GitHub-аккаунта или указать другие.
6. Далее откроется главный экран приложения.

> Если у вас нет аккаунта на GitHub, сначала зарегистрируйтесь на [github.com](https://github.com), а затем возвращайтесь к авторизации в приложении.

## 6. Обзор интерфейса

Главное окно GitHub Desktop состоит из нескольких ключевых зон:

- **Верхняя панель**:
  - **Current repository** — выбор репозитория, с которым вы сейчас работаете (можно переключаться между несколькими).
  - **Current branch** — переключение и создание веток.
  - **Fetch origin / Push origin / Pull origin** — кнопка синхронизации с удалённым репозиторием (текст меняется в зависимости от состояния: есть ли что скачать/загрузить).
- **Левая панель** (в зависимости от вкладки):
  - **Changes** — список изменённых файлов, которые ещё не закоммичены, плюс поле для сообщения коммита.
  - **History** — история всех коммитов в текущей ветке.
- **Правая часть окна** — diff (построчное сравнение) выбранного файла: что было добавлено (зелёным) и что удалено (красным).

## 7. Основной рабочий процесс (Workflow)

Стандартный цикл работы в GitHub Desktop выглядит так:

```
Клонировать/создать репозиторий → создать ветку → внести изменения →
закоммитить → отправить (push) → создать Pull Request → слияние (merge)
```

### 7.1. Клонирование существующего репозитория

1. В меню выберите **File → Clone Repository** (или сочетание клавиш `Ctrl+Shift+O` на Windows / `⌘⇧O` на Mac).
2. Появится окно с тремя вкладками:
   - **GitHub.com** — список всех репозиториев, к которым у вас есть доступ. Просто выберите нужный.
   - **GitHub Enterprise** — аналогично, если подключён корпоративный аккаунт.
   - **URL** — сюда можно вставить ссылку на любой Git-репозиторий (не только GitHub — подходит GitLab, Bitbucket, Azure Repos и другие). Работает с HTTPS- и SSH-ссылками.
3. Укажите локальную папку, куда сохранить репозиторий (**Local path**).
4. Нажмите **Clone**.

Важно: клонирование скачивает не просто файлы, а полную копию репозитория — со всей историей коммитов, ветками и тегами.

### 7.2. Создание нового репозитория

1. **File → New Repository** (`Ctrl+N` / `⌘N`).
2. Укажите:
   - **Name** — имя репозитория.
   - **Description** — необязательное описание.
   - **Local Path** — где на диске будет храниться репозиторий.
   - Опции **Initialize with a README**, выбор **Git ignore** шаблона и **License** — можно сразу настроить.
3. Нажмите **Create Repository**.
4. Чтобы опубликовать репозиторий на GitHub, нажмите кнопку **Publish repository** в верхней панели — появится диалог с выбором имени, описания и приватности (Private/Public).

### 7.3. Добавление уже существующей локальной папки с проектом

Если у вас уже есть папка с проектом на диске (например, инициализированная через `git init` в терминале):

1. **File → Add local repository**.
2. Укажите путь к папке.
3. Если папка ещё не является git-репозиторием, GitHub Desktop предложит создать его (`create a repository`).

### 7.4. Внесение изменений и просмотр diff

1. Откройте файлы проекта в любом редакторе (например, VS Code) и внесите изменения.
2. Вернитесь в GitHub Desktop — на вкладке **Changes** появится список изменённых/новых/удалённых файлов.
3. Кликните по файлу — справа отобразится построчный diff: добавленные строки подсвечены зелёным, удалённые — красным.
4. Флажками слева от файлов можно выбрать, какие именно файлы (или даже отдельные строки) включить в коммит, а какие оставить для следующего.

### 7.5. Создание коммита

1. В нижней части левой панели заполните:
   - **Summary** — краткое описание изменения (обязательно).
   - **Description** — подробное описание (необязательно).
2. При необходимости укажите **Co-authors** (соавторов коммита).
3. Нажмите **Commit to <имя-ветки>**.

### 7.6. Отправка изменений на GitHub (Push)

1. После коммита в верхней панели появится кнопка **Push origin** — нажмите её, чтобы отправить коммиты в удалённый репозиторий.
2. Если ветка ещё не опубликована на GitHub, кнопка будет называться **Publish branch**.
3. Чтобы получить изменения от других участников — используйте **Fetch origin** (проверить обновления) и **Pull origin** (скачать и влить изменения).

## 8. Работа с ветками (Branches)

Ветки позволяют изолировать работу над отдельной задачей, не затрагивая основную ветку (`main`/`master`).

1. Нажмите на название текущей ветки в верхней панели → **New Branch** (или `Ctrl+Shift+N` / `⌘⇧N`).
2. Укажите имя ветки и от какой ветки она будет создана.
3. Нажмите **Create Branch** — GitHub Desktop автоматически переключится на неё.
4. Чтобы переключиться между существующими ветками, снова откройте список веток и выберите нужную.
5. Чтобы слить одну ветку в другую: переключитесь на целевую ветку (например, `main`) → меню **Branch → Merge into current branch** → выберите ветку-источник → **Merge**.

---

## 9. Pull Request (PR)

Pull Request — это способ предложить свои изменения для проверки и включения в основную ветку проекта.

1. Убедитесь, что ваша ветка с изменениями отправлена на GitHub (**Push/Publish branch**).
2. В верхней панели нажмите **Create Pull Request** (или **Branch → Create Pull Request**, `Ctrl+R` / `⌘R`).
3. Откроется браузер со страницей создания PR на github.com, где нужно указать заголовок, описание и в какую ветку вливать изменения.
4. Уже существующие pull request — свои или коллег — можно открыть прямо в приложении: **Branch → Pull Requests** покажет список; двойной клик по PR откроет его локально для просмотра и внесения правок.

## 10. Синхронизация и работа с конфликтами

- GitHub Desktop показывает, если ваша локальная ветка отстаёт или опережает удалённую (счётчики коммитов "выше/ниже" рядом с кнопкой Push/Pull).
- Если при слиянии или получении изменений возникает конфликт (один и тот же участок кода изменён и локально, и на сервере), приложение подсветит конфликтующие файлы и предложит открыть их в текстовом редакторе для ручного разрешения. После правки нужно отметить конфликт как решённый и завершить коммит/слияние.

## 11. Управление коммитами

В истории (**History**) можно щёлкнуть правой кнопкой по коммиту и выбрать одно из действий:

- **Undo commit** — отменить последний коммит.
- **Amend commit** — изменить последний (ещё не отправленный) коммит: дополнить его файлами или переписать сообщение.
- **Revert commit** — создать новый коммит, который отменяет изменения выбранного (безопасно для уже запушенных коммитов).
- **Reset to commit** — откатить ветку к состоянию на момент выбранного коммита.
- **Cherry-pick** — перенести коммит в другую ветку.
- **Squash/Reorder commits** — объединить несколько коммитов в один или изменить их порядок (доступно через drag-and-drop в истории).

## 12. Настройки приложения

Через меню **File → Options** (Windows) или **GitHub Desktop → Preferences** (macOS) можно настроить:

- **Accounts** — подключённые аккаунты GitHub / GitHub Enterprise.
- **Git** — имя и email автора коммитов.
- **Appearance** — светлая/тёмная тема или автоматическая (по системе).
- **Editor** — редактор по умолчанию, который будет открываться при клике «Open in your external editor» (VS Code, Sublime Text, Atom и др. — определяются автоматически, если установлены).
- **Shell** — терминал, открываемый через «Open in command line» (PowerShell, Git Bash, Terminal и т.д.).
- **Advanced** — прокси, статистика использования, обработка больших файлов (Git LFS).

## 14. Обновление и удаление

- **Обновление**: GitHub Desktop проверяет обновления автоматически и предлагает установить их при запуске (уведомление в правом нижнем углу). Ручную проверку можно запустить через меню **Help → About** (или **GitHub Desktop → About GitHub Desktop** на Mac).
- **Удаление**:
  - **Windows**: через **Параметры → Приложения → Приложения и возможности** найдите GitHub Desktop и нажмите «Удалить».
  - **macOS**: перетащите приложение из папки **Applications** в корзину.

## 15. Частые вопросы

**Нужно ли знать команды Git, чтобы пользоваться GitHub Desktop?**
Нет. Для большинства повседневных задач (коммиты, push, pull, ветки, pull request) терминал не нужен — всё делается через интерфейс. Только продвинутые операции (например, интерактивный rebase) пока доступны только через командную строку Git.

**Можно ли работать не только с GitHub.com?**
Да. Через вкладку **URL** при клонировании можно подключить любой Git-репозиторий — GitLab, Bitbucket, Azure Repos, self-hosted сервер. Но функции pull request работают только с GitHub.com и GitHub Enterprise.

**Поддерживается ли Linux?**
Официально нет, но существуют неофициальные сборки от сообщества (в разделе Community Releases репозитория проекта на GitHub).

**Что делать, если пропал доступ / истёк токен?**
Если организация использует SSO, при истечении сессии или токена GitHub Desktop сам предложит заново авторизоваться перед следующим push.
